Purpose and reference behavior

1. Build an independent Quill-project to IMM converter that matches the existing
   Quill application's IMM export. Quill's exported files are the behavioral
   reference, including what is preserved, transformed, baked or omitted.
2. This is separate from the Open Brush brush-compatibility investigation. Its
   restrictions on brush textures, lighting and mesh substitution do not define
   the scope of this converter.
3. Existing Quill animation/export behavior is a mapping to reproduce, not a new
   IMM feature set for the user to design. Investigate apparent gaps against
   Quill's actual IMM output before proposing native format or player changes.
4. Behavioral agreement is required; binary byte identity is not assumed.
   Existing local candidate reference exports have now been inspected as described
   in the C0 findings below; no controlled Quill re-export or visual parity check
   has been performed.

What exists

1. Bundled SharpQuill reads Quill.json and Quill.qbin into a Sequence: group trees,
   native paint strokes, drawing/frame tables, layer properties, animation keys,
   viewpoints, camera FOV and embedded picture/sound data, with the limits below.
2. Quill's four native brush sections already correspond to IMM Ribbon, Cylinder,
   Ellipse and Cube. Ordinary Quill paint does not require the separate Open Brush
   brush adapters, additive blending or analytic-softness proposals.
3. libImmExporter already writes IMM documents and native layer structures.
   Managed ImmExporter.cs wraps sequence, groups, paint, drawings, elements,
   points, frame references, spawn areas and file/memory output. Low-level bindings
   exist for animation keys and paint repeat count.
4. Native IMM has hierarchy, timing, picture and sound structures. Model metadata
   and bounded mesh serialization/deserialization are also implemented now
   (ca905f4b); model input is still skipped by SharpQuill. Native format support
   alone is not proof of Quill mapping or renderer parity.
5. The checked repository has IMM-to-Quill conversion through SharpQuillCompat and
   ImmToQuillConverterEditor, but no direct Quill-to-IMM conversion entry point
   was found. Existing native paint/group export can be reused; further managed
   and native API work depends on the mappings required below. Do not assume
   every media/model capability is exposed through the Unity export ABI.
6. ImmAuthoringCompiler already forwards actual group/paint pivots and animation
   keys through the low-level exporter bindings. Its graph supports Group, Paint
   and SpawnArea, rather than picture/sound/model construction. Reuse that work
   where appropriate instead of treating all managed animation support as absent.
7. The first implementation candidate is SharpQuill -> ImmAuthoringDocument ->
   ImmAuthoringCompiler. Validate its no-flip transform representation, single
   document frame rate and root/chapter limitations against references before
   committing to that path. No converter mapping through this graph exists yet.

Missing work for a basic converter

1. Conversion entry point: read a Quill project, build an IMM export document,
   report errors/unsupported data and write the output safely.
2. Native stroke transfer: map the four sections and copy positions, orientation
   normals, drawing-view directions, widths, colours, opacity and rotational-opacity
   behavior with correct units/conventions; compute required bounds. Match Quill's
   own exported values rather than routing through Open Brush or Tilt strokes.
3. Scene transfer: preserve groups, names, local transforms, pivots, visibility,
   opacity, background and default viewpoint. The convenience group/paint methods
   in ImmExporter.cs still supply identity pivots; the authoring compiler already
   passes actual pivots. Choose a path that preserves actual source values.
4. Animation transfer: connect source drawings and hold-frame references, frame
   rates, key channels/interpolation, nested offsets/durations/repeats and root
   actions to existing IMM mechanisms. Avoid duplicate drawings for hold frames
   or baking animated layer transforms into every stroke point.
5. Media transfer: native picture/sound capabilities exist, but managed construction
   and converter wiring are incomplete: the Unity ImmExporter_* ABI has no
   picture/sound/model construction entry points. Preserve projection/viewer locking,
   embedded data, audio gain/loop/spatial properties and timing as Quill exports them.
   The reader fixes below address input, not this output/conversion work.
6. Reference checks: compare representative source projects with IMM files produced
   by Quill, then check appearance, timing, media and playback in the native player.
   The bridge is not implemented. C0 data comparisons have begun; end-to-end
   conversion and reference playback acceptance remain outstanding.

C0 reference inspection and reuse decision (2026-10-21)

1. Searched the 21-project source collection, co-located IMM files and the separate
   F:/Imm collection (2444 top-level IMM files). Asset-ID matches also exist for
   seven source folders named after published works. Matching names are candidate
   provenance only; these files were not freshly exported from Quill in this run.
2. Added read-only investigation tools under
   code/appImmStrokeReader/tools/QuillImmReference/. The Python inventory reads
   JSON and qbin stroke headers without loading vertices. The .NET inspector uses
   the production readers and compares unique hierarchy paths, then stored indices.
   It records SHA-256 hashes and reports skipped/mismatching shapes explicitly.
3. Inventory covered all 21 projects and 1231092 stroke-header occurrences across
   drawing declarations, including hidden content. None enabled rotational opacity.
   Visible mixed-rate content DOES exist: AlexsSciFiWorld_Phase4 contains paint at
   15, 24, 30, 56 and 60 fps. Fishgym2Example has visible 12 fps paint. These were
   already local resources; new mixed-rate fixtures are not required to begin.
4. Compared decoded paint in four candidate pairs. Point totals below exclude
   strokes skipped because their point counts differ:

   Case                Matched paint layers   Compared points   Shape issues
   taperecorder        1                      2048              1
   Fishgym2Example      1                      143833            0
   consul-room         14                     56706             21
   Snoopy              12                     921518            187

   These are data comparisons, not pass/fail or rendering results. The source
   taperecorder has 114 strokes/2069 points; one stroke has 21 source points versus
   20 reference points, leaving 113 strokes in the point comparison. The two IMM
   filenames in that folder have identical hashes.
5. taperecorder covers all four sections: Ribbon->1 (70 strokes), Cylinder->2 (6),
   Ellipse->3 (12), Cube->4 (26). Visibility modes agree for all 114 strokes. For
   compared points, maximum position component difference is 1.3411e-5 metres;
   normal difference 0.003065; direct colour difference 0.000893; alpha difference
   zero; width difference 2.2731e-5. Extra sRGB-to-linear conversion gives a much
   larger colour difference (0.28635). This supports direct attribute transfer for
   these decoded values, rather than introducing another colour transform.
6. Native paint export removes consecutive equal quantized positions while retaining
   endpoints. See toImmersiveLayerPaint.cpp's verticesToExport loop. It also quantizes
   positions/normals/colours/alpha/width. Differing point counts can therefore be
   codec behavior; the current inspector does not align or certify skipped strokes.
   Do not change geometry or introduce a custom simplifier merely to equalize counts.
7. All non-root hierarchy paths match in taperecorder (4 layers) and consul-room
   (25 layers). Compared paint transforms and pivots match exactly; consul-room
   provides substantial nonidentity transform/pivot coverage. In Fishgym and Snoopy,
   absent paint paths are statically hidden through the layer or its ancestors.
   Group structure remains present, including empty groups. Snoopy's visible camera
   is absent. This is evidence for export filtering, not proof of a universal rule
   for animated visibility or every non-paint type.
8. AlexsSciFiWorld_Phase4 was inspected in metadata-only source mode, avoiding
   allocation of its 1.48 GB source paint/media payloads. The native reference was
   still decoded normally. All 748 exported paint paths retain identical drawing
   counts and frame buffers, but every exported paint rate is 60 fps, matching the
   sequence rate. Its source rates were 60 (649 layers), 24 (94), 15 (3), 30 (1)
   and 56 (1). Fishgym likewise maps a 12 fps source paint layer to 24 fps with
   unchanged frame indices. A new per-layer authoring rate is not justified by
   these references: use the sequence rate for the initial mapping and validate
   playback before claiming timing parity.
9. Reflections survive export. Snoopy's visible Cable1 maps source Z to native 3;
   Alex has 87 matched reflected layers, including X->1. The current managed
   authoring transform and Unity export transform ABI cannot express those flags.
   This is a demonstrated shared capability gap. Preserve reflections through a
   focused additive extension before claiming broad corpus coverage; initially
   reject them explicitly rather than silently baking or dropping them.
10. In the large animated case, some native base transforms differ from the source
    static Transform field. For example Light/NewLayer0's native transform and its
    first exported transform key equal the first source transform key, not the
    source static translation. Of 24 differing base transforms, 14 match the first
    source transform key; the other ten remain unresolved. Investigate these C2
    mappings rather than inferring a global unit conversion or a static-paint blocker.
11. First C1 slice: implement SharpQuill -> ImmAuthoringDocument -> existing compiler
    for unreflected static paint/groups, using taperecorder and consul-room paint
    as initial references. Preserve local transforms/pivots and transfer native
    attributes directly; compute bounds with the existing compiler. Preflight raw
    layer types before SharpQuill can drop Model/Unknown. Explicitly reject or
    diagnose out-of-profile media, viewpoints, animation and reflection; output must
    identify any partial subset. No new graph type or frame-rate API is needed for
    this first slice. Navigation, animated mappings and media retain their own exits.
12. Place the runtime mapping in the imm-unity authoring assembly (or a consumer
    assembly referencing both packages), not in the lower-level stroke-reader
    assembly. An editor command can call that runtime mapping. Add safe output and
    structured conversion diagnostics rather than another scene representation.
13. Reports are under ignored artifacts/quill-reference/: source-inventory.json,
    taperecorder.json, fishgym.json, consul.json, snoopy.json and alex-metadata.json.
    They contain input hashes and private scene details; do not publish them as CI
    fixtures. Reader DLL SHA-256:

Five confirmed reader bugs and fixes

1. 5d191d4d - panorama names. The observed 360_Equirect_Stereo string previously
   became Unknown. Added the actual underscore aliases while retaining existing
   picture aliases and viewer-lock settings.
2. 1edf74b4 - minimal viewpoints. Missing Version/Sphere/translation/export fields
   previously caused parsing failure. Use known viewpoint defaults while preserving
   explicit fields, including false/zero.
3. c4d69441 - spatial sound properties. Positional/Flat type, attenuation mode/range
   and Cone angles/outside attenuation were present in source but ignored. Added
   enum values/model fields and parsing, with defaults for absent optional data.
4. fd36a10f - startup metadata. TrackingOrigin and AnimateOnStart were discarded.
   They are now nullable Sequence fields preserved by both reader and writer, so
   an explicit paused start is not confused with missing legacy metadata.
5. 2a9ffcb9 - embedded audio. The reader previously expected a byte length followed
   by an encoded audio file. All 34 real payloads began with zero and therefore
   returned empty audio. It now reads the actual header and wraps the observed
   interleaved 16-bit PCM in valid WAV bytes through SoundData.AudioBytes.
   Truncated, oversized and invalid payloads fail explicitly; unobserved encodings
   are not silently treated as supported.
6. At the 2026-10-15 checkpoint all five commits were pushed through 2a9ffcb9 after pulling
   (already up to date). No source Quill files or native shaders were changed.

Timing findings

1. Quill's stored timeline key/offset values use 12600 ticks per second, matching
   native piTick and ExportLayerTiming. At 24 fps one frame is 525 ticks; at 60 fps
   it is 210. The corpus has 18 sequence rates of 24, two of 60 and one omitted.
2. SharpQuill Keyframe<T>.Time's milliseconds comment is misleading. Current
   parsing passes key times through float before int. The maximum corpus key time
   is 14859810 and no integer key times were lost here. Longer-timeline precision
   is a potential issue, not a confirmed failure from this corpus.
3. Eleven layers have nonzero static StartOffset values. Preserve local timing,
   offsets, repeats and held references using Quill's output as the oracle.
4. Chapters has root Stop keys at 0, 3675 and 26775, plus MakeDefault at 50400,
   in stored ticks. It has one Sequence root, not a separate multi-document chapter
   container. Equal action names in source/target enums do not establish identical
   behavior; compare actual exported actions and playback boundaries.
5. Validate mappings before proposing native timing changes. Existing animation
   features are not new format-design decisions for the user.

Unverified content and non-playback metadata

1. Official Quill documentation describes OBJ/FBX reference-model import, with
   animated layer properties. Model is not merely an enum placeholder in that
   documented authoring application. However, no models appeared in the local
   corpus, and the target Quill application's IMM export/player behavior for them
   was not checked. The bundled SharpQuill reader currently skips Model/Unknown.
2. TwoDDepth exists in the reader enum but target application support was not
   established. Official docs describe cubemap pictures, while the local enum
   has no explicit cubemap entry. Neither absence nor a parser TODO proves that
   a feature is a placeholder. Seek reference behavior when a relevant case arises.
3. Native IMM Effect/Reference/Instance enum entries are not a list of Quill source
   features that must be invented in this converter.
4. Camera FOV/capture settings, gallery previews, lock/collapsed/bounding-box UI
   state and original import paths may be authoring/presentation metadata. Match
   Quill's IMM export rather than treating every source field as a player blocker.
   Gallery parsing is still a TODO, and nonempty Gallery picture writing currently
   throws; keep this distinct from required visible picture layers.
5. For unrepresented cases, follow the native exporter when suitable examples are
   available, and report unsupported data clearly. Do not delay ordinary corpus
   coverage to implement speculative behavior or silently discard unknown layers.
6. SharpQuill's project writer currently filters out Sound, Picture and Model
   children, and has no implementation writers for them. Reading their data does
   not imply complete Quill-project round-trip support. A direct Quill-to-IMM
   converter should consume the parsed source, rather than round-tripping through
   this writer. Detect unsupported layer types before the reader drops them.
