Purpose and reference behavior

1. Build an independent Quill-project to IMM converter that matches the existing
   Quill application's IMM export. Quill's exported files are the behavioral
   reference, including what is preserved, transformed, baked or omitted.
2. This is separate from the Open Brush brush-compatibility investigation. Its
   restrictions on brush textures, lighting and mesh substitution do not define
   the scope of this converter.
3. Existing Quill animation/export behavior is a mapping to reproduce, not a new
   IMM feature set for the user to design. Investigate apparent gaps against
   Quill's actual IMM output before proposing native format or player changes.
4. Behavioral agreement is required; binary byte identity is not assumed.
   Existing local candidate reference exports have now been inspected as described
   in the C0 findings below; no controlled Quill re-export or visual parity check
   has been performed.

What exists

1. Bundled SharpQuill reads Quill.json and Quill.qbin into a Sequence: group trees,
   native paint strokes, drawing/frame tables, layer properties, animation keys,
   viewpoints, camera FOV and embedded picture/sound data, with the limits below.
2. Quill's four native brush sections already correspond to IMM Ribbon, Cylinder,
   Ellipse and Cube. Ordinary Quill paint does not require the separate Open Brush
   brush adapters, additive blending or analytic-softness proposals.
3. libImmExporter already writes IMM documents and native layer structures.
   Managed ImmExporter.cs wraps sequence, groups, paint, drawings, elements,
   points, frame references, spawn areas and file/memory output. Low-level bindings
   exist for animation keys and paint repeat count.
4. Native IMM has hierarchy, timing, picture and sound structures. Model metadata
   and bounded mesh serialization/deserialization are also implemented now
   (ca905f4b); model input is still skipped by SharpQuill. Native format support
   alone is not proof of Quill mapping or renderer parity.
5. The checked repository has IMM-to-Quill conversion through SharpQuillCompat and
   ImmToQuillConverterEditor, plus the initial QuillToImmConverter static entry point.
   Existing native paint/group export is reused; further managed
   and native API work depends on the mappings required below. Do not assume
   every media/model capability is exposed through the Unity export ABI.
6. ImmAuthoringCompiler already forwards actual group/paint pivots and animation
   keys through the low-level exporter bindings. Its graph supports Group, Paint
   and SpawnArea, rather than picture/sound/model construction. Reuse that work
   where appropriate instead of treating all managed animation support as absent.
7. The first implementation candidate is SharpQuill -> ImmAuthoringDocument ->
   ImmAuthoringCompiler. The graph now preserves reflection flags through additive
   offline APIs. Its single document frame rate and root/chapter limitations still
   require reference-backed mappings. The initial converter uses this graph/compiler.

Remaining work for a basic converter

1. Static entry point and safe output are implemented. Broader conversion remains
   outstanding; do not treat successful explicit paint-only output as full parity.
2. Static native stroke transfer is implemented: four sections, positions, orientation
   normals, drawing-view directions, widths, colours, opacity and rotational-opacity
   behavior and computed bounds. Local reference paint subsets match exactly after
   native decoding. Native visual acceptance remains outstanding.
3. Static scene transfer preserves groups, names, local transforms, pivots, visibility,
   opacity and background. Default viewpoint/navigation remain outstanding.
   The convenience group/paint methods
   in ImmExporter.cs still supply identity pivots; the authoring compiler already
   passes actual pivots. Choose a path that preserves actual source values.
4. Animation transfer: connect source drawings and hold-frame references, frame
   rates, key channels/interpolation, nested offsets/durations/repeats and root
   actions to existing IMM mechanisms. Avoid duplicate drawings for hold frames
   or baking animated layer transforms into every stroke point.
5. Media transfer: native picture/sound capabilities exist, but managed construction
   and converter wiring are incomplete: the Unity ImmExporter_* ABI has no
   picture/sound/model construction entry points. Preserve projection/viewer locking,
   embedded data, audio gain/loop/spatial properties and timing as Quill exports them.
   The reader fixes below address input, not this output/conversion work.
6. Reference checks: compare representative source projects with IMM files produced
   by Quill, then check appearance, timing, media and playback in the native player.
   Static conversion and native data comparisons exist; full conversion and
   reference playback acceptance remain outstanding.

C2 evaluation contract: source review, playback acceptance outstanding

1. Metadata inspection reads the serialized base transform, not an evaluated
   playback frame. fiLayer::Read reads laTran from the layer descriptor and passes
   it to Layer::Init. StrokeReader_LoadFromFile imports, then captures metadata;
   StrokeStore::CaptureSequenceMetadata records Layer::GetTransform separately
   from the complete animation-key list. Do not use a base-field mismatch alone
   as proof that the transform channel was lost or playback will differ.
2. Layer::SetStateAt in code/libImmImporter/src/document/layer.cpp replaces the
   effective transform from its keys. Before the first transform key it selects
   that first value without interpolation; after the last it holds the last value.
   Between interpolated transform keys it mixes key*pivot and then multiplies by
   inverse(pivot). Before the first visibility key it instead sets visibility
   false. Thus visibility and transform channels cannot share a generic fallback
   rule inferred only from their enum names.
3. Native easing uses t^3 for EaseIn, 1-(1-t)^3 for EaseOut and t^2*(3-2*t) for
   Smoothstep. Quill enum integers differ from native integers: map named values
   explicitly. The observed reference audit verifies None/Linear/Smoothstep only;
   matching enum names/formulas does not replace Quill playback evidence for the
   other two modes.
4. C2 acceptance must evaluate pre-first-key, exact-key, interpolation midpoint
   and post-last-key times, including pivots, nested offsets/repeats and held
   drawings. Also compare first presentation, pause/start, seek and restart so
   serialized base fields do not mask a startup difference. The reason Quill
   exported particular base values remains unknown. Preserve source static
   fields and keys as separate data pending those checks; do not bake arbitrary
   later-key values into the converter to make metadata fields match.
5. Further metadata audit of the same large reference pair found 1,156 matched
   visibility keys with identical count/time/value/interpolation. Opacity retained
   133 keys with matching semantics; 914 source single opacity keys at time zero
   were absent from the native key lists, but every value matched the native
   static opacity (including non-unit values). Offset retained 684 keys with
   matching semantics; 465 omitted source keys were all None/zero at time zero.
   There were no other count differences or retained-key semantic differences in
   these three channels among matched layers. This demonstrates constant-key
   collapse in this reference pair, not permission to discard animated channels.
   Extra equivalent constant keys need not be removed just to reproduce the
   reference's serialized layout: acceptance concerns behavior, not binary identity.
   Local evidence: artifacts/quill-reference/alex-other-key-recheck.json. Root
   actions and playback behavior are outside this audit.

Timing findings

1. Quill's stored timeline key/offset values use 12600 ticks per second, matching
   native piTick and ExportLayerTiming. At 24 fps one frame is 525 ticks; at 60 fps
   it is 210. The corpus has 18 sequence rates of 24, two of 60 and one omitted.
2. SharpQuill Keyframe<T>.Time's milliseconds comment is misleading. Current
   parsing passes key times through float before int. The maximum corpus key time
   is 14859810 and no integer key times were lost here. Longer-timeline precision
   is a potential issue, not a confirmed failure from this corpus.
3. Eleven layers have nonzero static StartOffset values. Preserve local timing,
   offsets, repeats and held references using Quill's output as the oracle.
4. Chapters has root Stop keys at 0, 3675 and 26775, plus MakeDefault at 50400,
   in stored ticks. It has one Sequence root, not a separate multi-document chapter
   container. Equal action names in source/target enums do not establish identical
   behavior; compare actual exported actions and playback boundaries.
5. Validate mappings before proposing native timing changes. Existing animation
   features are not new format-design decisions for the user.

Unverified content and non-playback metadata

1. Official Quill documentation describes OBJ/FBX reference-model import, with
   animated layer properties. Model is not merely an enum placeholder in that
   documented authoring application. However, no models appeared in the local
   corpus, and the target Quill application's IMM export/player behavior for them
   was not checked. The bundled SharpQuill reader currently skips Model/Unknown.
2. TwoDDepth exists in the reader enum but target application support was not
   established. Official docs describe cubemap pictures, while the local enum
   has no explicit cubemap entry. Neither absence nor a parser TODO proves that
   a feature is a placeholder. Seek reference behavior when a relevant case arises.
3. Native IMM Effect/Reference/Instance enum entries are not a list of Quill source
   features that must be invented in this converter.
4. Camera FOV/capture settings, gallery previews, lock/collapsed/bounding-box UI
   state and original import paths may be authoring/presentation metadata. Match
   Quill's IMM export rather than treating every source field as a player blocker.
   Gallery parsing is still a TODO, and nonempty Gallery picture writing currently
   throws; keep this distinct from required visible picture layers.
5. For unrepresented cases, follow the native exporter when suitable examples are
   available, and report unsupported data clearly. Do not delay ordinary corpus
   coverage to implement speculative behavior or silently discard unknown layers.
6. SharpQuill's project writer currently filters out Sound, Picture and Model
   children, and has no implementation writers for them. Reading their data does
   not imply complete Quill-project round-trip support. A direct Quill-to-IMM
   converter should consume the parsed source, rather than round-tripping through
   this writer. Detect unsupported layer types before the reader drops them.
