# Procedural Runtime Authoring Demo

Open `Scenes/ProceduralAnimationDemo.unity` and enter Play mode. The
`Procedural IMM Demo` component will:

1. Build a multi-frame, multi-strand ribbon using `ImmAuthoringDocument`.
2. Commit the complete animation through one `ImmAuthoringTransaction`.
3. Compile revision 1 to IMM bytes in memory and import those bytes into a new mutable document.
4. Verify that the import is lossless, safe to overwrite, and structurally equivalent to the source graph.
5. Query the imported layers, drawings, strokes, frames, and opacity animation keys.
6. Request the imported revision through `ImmAuthoringPreviewCoordinator`.
7. Load the compiled bytes directly into the native player and render them without writing an IMM file.
8. Retain the stable IDs assigned to the imported strokes, frame mappings, and animation keys.
9. Open a second transaction, replace imported stroke geometry, one frame mapping, and an opacity key by ID, and commit revision 2.
10. Replace the native preview with revision 2 while preserving playback state and time.
11. Report the running platform/architecture and supported authoring capabilities.
12. Report validation, compilation, serialization, source-inspection, and import progress.
13. Demonstrate controlled resource-limit, cancellation, and malformed-input failures while leaving the valid graph usable.

The generated byte size, source revision, and current state are visible on the
component while the scene runs. `Generated File Path` remains empty during the
default file-free preview. The component also reports import lossiness, whether
the source can be overwritten safely, imported layer/stroke counts, structural
differences, current authoring and installed revisions, representative stable
stroke, frame-mapping, and animation-key IDs, and the number of committed
modifications.

The component context menu also provides:

- **Generate and Play**
- **Round Trip Current Graph Through Memory Import**
- **Modify Existing Graph and Replace Preview**
- **Export IMM Only**
- **Unload Generated IMM**
- **Run Phase 6 Controlled Failure Checks**

**Generate and Play** is the file-free runtime path. By default it automatically
performs one visibly deformed revision-2 edit after the initial preview has
played for 1.5 seconds. **Round Trip Current Graph Through Memory Import**
exports the current mutable graph to memory, imports it, verifies its supported
round trip, adopts the imported graph, and replaces the preview. **Modify
Existing Graph and Replace Preview** repeats the stable-ID mutation and
replacement process on demand. **Export IMM Only** is a separate demonstration
of `ImmAuthoringCompiler.ExportToFile`; it writes
`procedural-ribbon.imm` under `Application.persistentDataPath` and reports the
full path on the component.

The scene is intentionally an engine sample: it uses inspector properties and
context-menu commands, without application-level animation-editor UI.

The coordinator is the Phase 4 engine path used by an external editor. The
import, lossiness, structural-comparison, and imported-graph mutation steps
exercise the Phase 5 engine path. A later
request supersedes queued, compiling, or loading work. The installed native
document stays visible until its replacement is fully loaded, and it also stays
installed if replacement compilation or loading fails. Request state,
revision, byte count, compilation time, player-load time, and total latency are
available through `ImmAuthoringPreviewRequest`.

The component's Phase 6 fields show the capability query, latest progress stage
and fraction, and the three expected controlled failure codes. These are engine
diagnostics in the Inspector, not product editor UI.
## Phase 1 lifecycle and performance gate

Add `ImmRuntimeAnimationSpike` to a scene with the existing IMM player setup.
The component context menu provides:

- **Run Animation Spike** for one end-to-end cycle.
- **Run 100-cycle Lifecycle Gate** for the Phase 1 soak gate.

Each cycle builds a mutable multi-frame paint document, compiles it to an owned
memory buffer using the batch point ABI, loads it into the native player, seeks,
plays one rendered frame, and unloads it. Logs use `[IMM_AUTHOR_SPIKE_P1]` and
report construction, graph compilation, serialization, load-to-ready,
first-render timing, output size, and memory deltas. The gate stops immediately
if the manager's live-document or retained input-buffer count does not return to
its starting value after an unload.
